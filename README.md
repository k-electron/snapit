# snapit

A brilliantly simple macOS menu bar app for taking a Capture, marking it up and getting it onto the clipboard or disk. It uses 0% CPU and about 15 MB at rest. macOS 26 or later, Apple silicon only. MIT licensed.

The vocabulary (Capture, Editor, Annotation, Export and so on) is in [GLOSSARY.md](GLOSSARY.md).

## Layout

| Path | What it is |
|---|---|
| `snapit/` | The menu bar app (agent, SwiftUI `MenuBarExtra`). One Swift file per feature: `Capture/` (Capture source, Screen Capture flow, the hand-off to the Editor), `Helper/` (starting the Editor helper), `Shortcuts/` (KeyboardShortcuts and its test replacement), `Menu/`, `Commands/`. |
| `snapit-editor/` | The Editor helper, nested at `snapit.app/Contents/Helpers/snapit Editor.app`. An agent with no Dock icon until a window shows, then a regular app; it quits when its last window closes. Same name and icon as snapit. `Editor/` holds the Editor, one file per tool, toolbar item and Export stage, each with a registry. |
| `Shared/` | Swift compiled into both targets: the engine wrapper, the Capture file (how pixels move between the processes), Settings keys, the socket command enum and registry, `TestMode` and the edges it replaces (`Shared/Edges/`: pasteboard, defaults, Save location, permission), the app icon. |
| `engine/` | The Rust engine: a static library behind a C ABI. `engine/include/snapit_engine.h` is generated by cbindgen and committed. |
| `snapit.xcodeproj` | Buildable folders, three targets: `snapit`, `snapit-editor` and `Engine` (the Run Script phase that runs Cargo). |
| `scripts/` | Build, header and test scripts. `scripts/run/` holds the scripted run's helpers, flows and PNG checker. |

## Build

Dependencies: [KeyboardShortcuts](https://github.com/sindresorhus/KeyboardShortcuts) 3.x (MIT) through Swift Package Manager, pinned in `snapit.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`.

You need Xcode 26 or later, [rustup](https://rustup.rs) and [cbindgen](https://github.com/mozilla/cbindgen) 0.29.4 (`cargo install cbindgen --version 0.29.4 --locked`).

```sh
xcodebuild -project snapit.xcodeproj -scheme snapit -configuration Release \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath build/DerivedData.noindex build
```

Xcode builds the engine through the `Engine` target, which runs `scripts/build-engine.sh`. The script finds `cargo` itself, so no shell profile is needed. The Rust toolchain version is pinned in `rust-toolchain.toml`. Builds are ad-hoc signed.

After changing the engine's C interface, run `scripts/generate-header.sh` and commit the header.

## Test

```sh
scripts/test.sh          # everything
scripts/test.sh engine   # repo checks, Cargo fmt, clippy, tests and the header check only
```

`scripts/test.sh` runs, in order:

1. Repo layout checks.
2. `cargo fmt --check`, `cargo clippy` and `cargo test`. The Cargo tests call the engine through the same C-ABI functions Swift calls.
3. The cbindgen header check: the committed header must match the engine.
4. The Xcode build.
5. `scripts/check-bundle.sh`: the Editor helper is nested in `Contents/Helpers`, both bundles verify with `codesign --verify --strict`, same name and icon.
6. `scripts/check-run.sh`, the scripted whole-app run. It starts snapit in test mode (`SNAPIT_TEST_ROOT` points at a fresh temporary folder), so the Capture source returns fixture images, Screen Recording reads as granted, the clipboard is a private pasteboard, and the Save location, cache and defaults live in the temporary folder. It drives the menu item and the Shortcut for a Screen Capture at 1x and 2x, opens each Capture in the Editor helper (Dock icon while it is open, process lifecycle, memory-mapped Capture file), copies it with ⌘C and checks the PNG on the pasteboard pixel by pixel and for its `pHYs` and ICC metadata, closes Editors with Esc and Delete Capture, starts and quits the Editor helper, measures idle CPU and memory over repeated Editor cycles, and asserts that your real preferences, cache folder and clipboard were not touched.

[docs/testing.md](docs/testing.md) explains test mode and how to add a flow, a fixture, a test-mode command or an engine test.

CI (`.github/workflows/ci.yml`) runs `scripts/test.sh` on the `macos-26` arm64 runner. OSV-Scanner runs on Ubuntu from `.github/workflows/osv-scanner.yml`.

## Install

snapit is not notarized. The first time you open it, macOS says it can't verify it:

1. Open snapit. macOS blocks it.
2. Open System Settings > Privacy & Security.
3. Click **Open Anyway**, then enter your password.
